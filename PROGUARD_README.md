**Shrinking, obfuscating, and minifying Android APKs without Android Studio or Gradle.**

## <img src=".github/assets/icons/bolt.svg" width="20"> 1. Core Architecture & Concept

Google's modern code shrinker and optimizer, **R8**, is fully integrated inside `d8.jar`. You do not need to download ProGuard or any separate tools. The same JAR entry point can execute either plain debug compilation (D8) or full release shrinking and obfuscation (R8).

```bash
# Debug compilation: Java .class -> Android DEX (no shrinking)
java -cp d8.jar com.android.tools.r8.D8 ...

# Release compilation: Shrink + Obfuscate + Optimize -> Android DEX
java -cp d8.jar com.android.tools.r8.R8 ...
```

> [!NOTE]
> R8 performs dead-code elimination, member inlining, package flattening, class renaming, and DEX byte-code optimization in a single pass.

## <img src=".github/assets/icons/terminal.svg" width="20"> 2. Minimal `proguard.pro` Configuration

When running R8 without Gradle, you must provide a clean ProGuard rules file. Keep essential Android entry points (such as `Activity` and `SurfaceView` callbacks) and let R8 optimize the remaining codebase.

```proguard
# Preserve main application entry points
-keep public class * extends android.app.Activity
-keep public class * extends android.view.SurfaceView

# Preserve essential lifecycle methods
-keepclassmembers class * extends android.app.Activity {
    protected void onCreate(android.os.Bundle);
    protected void onDestroy();
}

# Preserve SurfaceView callbacks for canvas rendering
-keepclassmembers class * extends android.view.SurfaceView {
    public void surfaceCreated(android.view.SurfaceHolder);
    public void surfaceDestroyed(android.view.SurfaceHolder);
    public void surfaceChanged(android.view.SurfaceHolder, int, int, int);
    public boolean onTouchEvent(android.view.MotionEvent);
}

# Optimization settings
-dontwarn **
-allowaccessmodification
-dontpreverify
```

## <img src=".github/assets/icons/layers.svg" width="20"> 3. Replacing D8 with R8 in the Build Chain

In a release build, replace the standard `D8` invocation with `R8`, passing your ProGuard configuration (`--pg-conf`) and output mapping file (`--pg-map-output`).

### Debug Build Step (D8):
```bash
java -cp d8.jar com.android.tools.r8.D8 \
  --output build/dex \
  --lib android.jar \
  $(find build/classes -name "*.class")
```

### Release Build Step (R8):
```bash
java -cp d8.jar com.android.tools.r8.R8 \
  --release \
  --min-api 26 \
  --lib android.jar \
  --output build/dex \
  --pg-conf proguard.pro \
  --pg-map-output build/mapping.txt \
  $(find build/classes -name "*.class")
```

## <img src=".github/assets/icons/package.svg" width="20"> 4. Post-Compilation & Packaging

Once `classes.dex` is generated by R8, the rest of the zero-Gradle build pipeline remains identical: copy `resources.apk`, inject `classes.dex`, align with `zipalign`, and sign with `apksigner`.

```bash
# 1. Prepare base APK package with resources
cp build/apk/resources.apk build/apk_final/app-unsigned.apk

# 2. Inject R8-compiled DEX into the zip archive
cd build/dex && zip -u ../apk_final/app-unsigned.apk classes.dex && cd ../..

# 3. Align zip structures to 4-byte boundaries
zipalign -f 4 build/apk_final/app-unsigned.apk build/apk_final/app-aligned.apk

# 4. Sign the final APK
java -jar apksigner.jar sign --ks debug.keystore --ks-pass pass:android --out MyApp-release.apk build/apk_final/app-aligned.apk
```

## <img src=".github/assets/icons/book.svg" width="20"> 6. Retracing Stack Traces with `mapping.txt`

R8 aggressively renames classes and methods to short symbols like `a`, `b`, and `c`. If a crash occurs in production, the obfuscated stack trace must be de-obfuscated using R8's built-in `Retrace` tool and your saved `mapping.txt`.

```bash
# Retrace obfuscated stacktrace to readable Java source lines
java -cp d8.jar com.android.tools.r8.retrace.Retrace build/mapping.txt stacktrace.txt
```

> [!TIP]
> Always archive `mapping.txt` alongside every release build artifact.

## <img src=".github/assets/icons/package.svg" width="20"> 7. Generating a Release Keystore

For production distribution (e.g. Google Play or custom distribution channels), generate a dedicated 2048-bit RSA release keystore:

```bash
keytool -genkey -v \
  -keystore release.keystore \
  -alias releasekey \
  -keyalg RSA -keysize 2048 -validity 25000 \
  -storepass YOUR_PASSWORD -keypass YOUR_PASSWORD \
  -dname "CN=Your Name, O=Your Company, C=US"
```

> [!WARNING]
> Keep `release.keystore` and its passwords in a secure location. Losing this key prevents publishing future updates for your application identity.
